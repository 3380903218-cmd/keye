# 从中文工作簿到Gephi：双层传播网络

版本日期：2026-10-13（新加坡）。权威输入是已保存的“中文记录工作簿整理版”；转换读取其中的事件、参与角色、对象、作品、复制品和来源登记，不读取示范行来创建关系。

## 直接打开已生成文件

在Gephi选择 **File → Open（⌘O）**，打开本文件夹根目录 **双层传播网络.gexf**。导入报告应显示 **46节点、57边、Directed**。使用新工作区，保留之前8节点试点工程。

图已带初始坐标、颜色和大小。太小可点击画布左下方适应全图的放大镜按钮；标签开关在画布底部Nodes尺寸滑块右侧的“小圆圈＋字母a”，鼠标悬停提示Show Node Labels。T控制标签大小模式。如标签遮挡，可运行Noverlap，或仅显示选择节点的标签。

在Data Laboratory查看节点的NodeType、FullLabel、RecordStatus、Notes，及边的Relation、Role、EventId、ReadingIds、SourceRef、Locator。缩短的显示标签不删除完整名称，FullLabel保留原文工作名称。

需要分享图时，在Preview中另启用节点标签和箭头、刷新，再导出SVG或PNG；通过Save As保存原生`.gephi`工程。原工作簿没有被修改。

## 表格怎样映射到节点和边

| 工作簿内容 | Gephi中的表示 |
|---|---|
| 现有主体ID | 人物、机构、政府和考察队节点；只输出本视图实际关联的主体 |
| 对象与批次 | 原物Object与批次／工作集合Collection节点；B号是分析ID，不是馆藏号 |
| 事件整理 | 每个EventId对应一个事件节点，保存行为、日期、状态和待核项 |
| 参与角色 | 有主体ID、事件ID和明确角色的一行转成主体→事件的关联 |
| 作品与载体 | Work节点，保留工作命名、转引和原件获取限制 |
| 复制品登记 | Representation节点；本版R0001是待逐张识别的照片组 |
| 阅读记录和来源 | 边、事件的证据属性及独立来源表，不自动成为早期传播作品节点 |

例如DH001：

```text
N002 王圆箓 → DH001 取得事件 → N006 斯坦因考察队
B0001 所涉批次 → DH001
N004 蒋孝琬 → DH001（谈判／搬运参与）
```

这里保留蒋的参与角色，不补画蒋个人交出材料的转移。

例如KE007：

```text
B0010 所查写本集合 → KE007 备忘录形成
N012 伯希和 → KE007（作者角色）
N005 斯坦因 → KE007（请求者角色）
KE007 → W001 备忘录
```

W001未独立核原稿和正文，且使用工作命名；事件→作品的边表示来源所记形成载体，不表示已经公开发表。摄影组R0001也不表示具体影像已取得或全部写本均有照片。

关系方向由Relation解释：transfer_from为转出／拨送主体→事件；transfer_to为事件→接收机构／行动；subject_of_event为对象→事件；participant_in_event为人物→事件；produces_work和produces_representation分别为事件→载体／复制品组。审阅图PE001使用dispatch_destination，表示文中送寄目的方，不自动证明实际收件。不能把图中每条箭头都解释为物件移动。

重复的端点角色与参与行合并为同一条关联边，多角色留在Role字段，Weight仍为1。未知人物不生成匿名人物节点，不按同文共现、相同题名或笼统合作猜测关系。只有“参与角色”表中的明确结构化角色转换为人→事件边；叙述者或自由文字中提到的人名不会自动连边。

对象表中有“有关联、成员未核”的集合对应，它们保存在RelatedCollectionNote属性，没有强画成包含、同一物或逐件流转关系。

## CSV格式与手动导入

Gephi需要两张表：

```csv
Id,Label,NodeType
N004,蒋孝琬,Person
DH001,DH001 斯坦因首次协议取得,Event
```

```csv
Id,Source,Target,Type,Weight,Relation
E_DH001_N004_DH001,N004,DH001,Directed,1,participant_in_event
```

这是实际映射的一小部分示例；完整CSV包含来源、日期和角色属性。Source和Target必须使用节点Id，不使用中文Label。

如果从CSV开始，新建空白工作区，在Data Laboratory依次导入同一文件夹的nodes.csv（Nodes table）、edges.csv（Edges table）。编码UTF-8，分隔符逗号，Type为Directed；Weight为数值，YearStart/YearEnd/EventCount/ReviewRequired为整数，其他字段为字符串。不要自动创建未知节点。

已经打开GEXF时不要再次追加配套CSV，以免重复。`事件原始记录.csv`等文件是研究表快照，不能直接当作Gephi边表导入。

官方格式说明：[Gephi CSV](https://docs.gephi.org/desktop/User_Manual/Import/CSV_Format/)、[Gephi GEXF](https://docs.gephi.org/desktop/User_Manual/Import/GEXF_File_Format/)。

## 日期、边权和计数

文件是静态图。YearStart与YearEnd保留年精度与明确时间界限，不能自动生成连续保管区间或精确动态图。默认以日期说明中的首个现代年作为事件年；明确year_range才提取两端。743这类写本自身纪年不会当成现代事件日期。

所有边等权。57条边是17条记录的主体、对象和载体关联，不是57次流转；同一事件在多条边上重复出现。按不同EventId计数，不能加总边上的EventCount来求历史事件总数。捆、箱、卷、粘片本不能直接作可比边权。

NodeType用于类型着色。人物橙色、考察队蓝色、机构绿色、政府紫色、对象和集合棕黄色、作品紫红色、复制品粉色、事件灰色；意向事件为金黄色，待核事件在审阅图为灰色且标签含[待核]。布局只用于显示，不是地理距离或传播速度。

主图两组件和审阅图三组件保留数据中的断链与范围缺口，不强行接通。多种节点类型的Degree含义不同；人物、事件和作品不宜直接混排成历史重要性榜单。

## 更新Excel后重新转换

先保存Excel文件，再运行转换；未保存的单元格不会进入文件。新增事件必须有唯一事件ID、关联阅读ID和状态，参与人及对象等必须在相应登记表存在。表头保持当前名称。

本文件夹的export_gephi.py与项目06_notes中的脚本相同，可读取更新后的XLSX并重新生成视图。默认输出已存在时脚本拒绝覆盖。建议先生成新文件夹，再检查计数和待核名单。

如本机Python缺依赖，可在本文件夹创建独立环境：

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install openpyxl networkx numpy
./.venv/bin/python export_gephi.py --output ../双层传播网络_Gephi_v2
```

openpyxl用于读取Excel；NetworkX和numpy用于初始布局与独立解析。没有布局依赖时仍可生成网格坐标，再到Gephi调整。要处理另一个工作簿，使用 `--workbook "/完整路径/工作簿.xlsx"`。
